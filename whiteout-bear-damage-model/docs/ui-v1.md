# Stage 25 UI（v0.1 历史说明；当前规则见 ui-v0.2.md）

现有 React/Vite UI 在原页面上扩展，没有重写或部署。

## 输入

- 兵种等级：T1–T10、T10-FC1–FC10、T11-FC5–FC10、T12-FC10。
- v0.1 曾保留防御、生命输入；v0.2 普通 UI 已删除这些当前输出不使用的字段。
- 车头、0–4 个可重复车身技能、专家、城镇 Buff、宠物、专武及兵种技能等级。
- 初始验证预设为盾1,824、矛1,823、射178,723，原始阵容总兵数为182,370。`baseMarchCapacity` 只由这三个原始兵数自动求和，UI 不再提供重复的“基础出征容量”输入；“其他固定容量”也不展示，底层该扩展值固定为0。
- 猎手之心 0–11，巨熊克星 0–10；宠物四项 0–10；炽火燧星（射T12技能）和烈辉战阵（矛T12技能）0–24。所有这类有限整数集合均使用下拉选择，自由兵数与战报百分比继续使用数值输入。
- “战报与阵容”标题下显示“打熊阵容无宠无药打野怪数据”，仅说明战报基础属性的取得条件，不会自动扣除或修改任何输入属性。

## 展示规则

- UI 能展示等级不代表一定能计算；缺少 Ct 时显示“暂无计算常数 / 暂不可计算”，不插值。
- RULE_UNKNOWN 显示“待确认”、技能名称与具体 pendingReason，且不计伤害；普通界面不暴露 supported/pending 等内部状态词，也不使用“x已确认/y待确认”计数。
- 当前用户可见 RULE_UNKNOWN 为0；格温不再显示“有待确认技能”。四个 DATA_SOURCE_UNCERTAIN 占位仍只保留在底层审计中。
- DATA_SOURCE_UNCERTAIN 占位英雄（丽娅拉、艾丝蒂拉、埃莉诺、弗洛拉）隐藏。
- 尼莫作为盾兵车头可手动选择并进入优化；战前宣言、剑术指导、精湛剑术全部进入打熊计算，专武攻击增益有效。三断斩、剑气、孤傲仍是探险技能，不进入打熊计算。
- 兵种技能和火晶技能按 T/FC 等级自动解锁，不提供会导致重复计算的手动勾选。
- 英雄选项中的数值由结构化 Skill/SkillEffect 数据生成；统一按满级计算，普通 UI 不重复显示“5级”。
- 四车身下拉按九种技能效果展示，不再逐个列英雄；来源英雄仅在下方详情展示。同一效果选择两份时显示选择数量2和该 skill 小区合计，例如减防+50%。手动允许四份相同技能，自动优化则每种最多两份。正常效果不显示“supported/confirmed/计入伤害”等开发状态。
- 优化比例统一显示到 0.01%。比例校验容忍半个显示单位以内的 IEEE-754 误差，整数兵数分配仍使用 largest remainder method。
- 计算后可展开“当前乘区明细”，按回合和兵种分别显示基础 D0、战报攻击/穿透倍率、Buff 攻击/穿透/减防、Skill 各小乘区、易伤、兵种克制与 Expert；Buff 和 Skill 不合并显示。
- 表单布局的 Grid/Flex 子项统一允许收缩，输入、下拉与技能说明的宽度不超过卡片；窄窗口下多列自动切换为两列或单列。
- 应用优化方案时只将方案比例按当前原始总兵数重新分配回输入框，不把扩容后的最终兵数当成新的基础容量，避免重复扩容。

结果显示最终容量、10回合期望总伤害、各兵种与逐回合明细、已应用/跳过技能和优化结果。逐回合表只显示普通伤害、extraDamage 与最终伤害，不再展示“额外攻击”列。优化器继续按同一正式十回合入口的期望总伤害评分。
