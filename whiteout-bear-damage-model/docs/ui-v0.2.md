# v0.2 双输入与伤害区间

## 输入模式

- 战报模式：使用“无宠无药打野怪”的三兵种兵数、等级、攻击和穿透。兵数是基础阵容，继续应用已确认的出征容量管线。
- 集结模式：部队通用攻击/穿透与各兵种攻击/穿透先在基础属性内加算；三兵种兵数是最终实际出征兵数，不再应用宠物、巨熊克星或城镇出征容量。
- 两种模式分别保存输入状态，切换模式不会清空另一套数据。

战报和集结模式都不显示防御、生命字段，因为当前模型只计算我方对熊输出。熊坑固定攻击 `25%` 在 UI 输入适配层加入基础攻击 A，不属于 Buff 或 Skill。

集结模式不提供顶部的通用攻击/穿透 Buff 输入。车头区域使用“集结专武攻击加成 %”与“集结专武穿透加成 %”直接记录本次集结实际提供的专武 Buff；两者分别进入 `buff.attack` 与 `buff.penetration`，绝不并入基础 A/P 或 Skill 乘区。英雄数据中的 `exclusiveWeaponBuffType` 与专武等级表继续保留为原始资料，当前普通 UI 不再据三个车头等级换算。

普通页面首次打开使用中性配置：数值和有限等级默认为0，城镇增益为“无”，车头、车身均为“不选择”；兵种等级使用最低合法等级 T1。测试和 benchmark 可以继续维护独立的非零样例。

## 95%伤害区间

区间端点是模型内10回合总伤害离散分布的 `2.5%` 与 `97.5%` 分位数，不使用 `mean ± 1.96σ`。状态规模可控时保留完整累计伤害路径并精确求分位；复杂配置超过历史状态上限时，在相同未来 BattleState 内对相邻历史伤害做确定性分箱，再求分位。该回退不使用随机采样，也不参与优化候选评分。

优化器继续只以10回合期望总伤害评分，不为每个候选生成分布。候选排名结束后，Web Worker 只为第1名方案额外生成一次95%区间；玩家点击“计算10回合伤害”时也会为当前配置生成区间。

## v0.4 战报英雄输入

战报模式的盾/矛/射各自增加“战报英雄”和“战报英雄专武等级”；实际车头区各自增加“车头专武等级”。战报英雄只用于静态攻击与专武穿透差值修正，不触发技能。正式计算和优化器共享 `resolveBattleReportEffectiveAttributes()`；集结模式不应用该差值。R、SR、吉娜没有专武，选择后等级固定0并禁用。详见 `report-hero-system.md`。
