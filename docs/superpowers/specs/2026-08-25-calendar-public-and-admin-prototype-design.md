# 活动日历公开页修复与管理端原型设计

日期：2026-08-25

## 范围

本次分为两个互不混淆的交付：

1. 修改公开活动日历及其首页嵌入入口。
2. 新建一个独立的活动日历管理 HTML 原型供验收，不替换、不引用、不接入现有管理端活动日历页面，也不调用真实管理接口。

## 公开活动日历

### 首页入口

- 首页“全部”分栏不显示活动日历内容。
- 只有用户点击“活动日历”分栏时，才创建并加载日历 iframe。
- 嵌入区域明确显示“当前为活动日历预览”。
- 嵌入区域提供“打开完整日历”按钮，打开 `/function/calendar.html`。

### 主题按钮

- 活动日历页不显示公共主题脚本自动注入的 `#themeToggleBtn.wjdr-theme-fab` 悬浮按钮。
- 只限制活动日历页，不改变其他工具页的主题切换行为。
- 日历继续使用现有淡暖色视觉，不新增替代主题按钮。

### 横屏与竖屏查看

- 完整日历工具栏新增“竖屏查看”和“横屏查看”按钮。
- 用户选择保存在当前浏览器会话或本地设置中，切换周/月、上一段/下一段时不重置。
- 竖屏查看使用紧凑七列：七天必须在视口内完整显示，不横向滚动；分类名称允许缩写，日期显示紧凑格式，活动块最多显示两行，点击查看完整详情。
- 横屏查看使用舒展七列：显示更完整的分类、日期和活动名称，仍不需要左右滚动。
- 手机上点击横屏查看时，优先申请全屏并调用 Screen Orientation API 请求横屏；浏览器不支持或拒绝时，仍切换到横屏布局并提示用户旋转设备。
- 切换回竖屏时退出方向锁定；不能强制解除系统方向时不得报错。
- 电脑端保留两个查看按钮，作为布局预览控制，不尝试强制操作系统旋转。

### 嵌入预览

- `?embed=1` 模式显示轻量预览提示栏，不显示完整页固定标题栏。
- 预览可以保留当前周日程，但不承担完整操作说明。
- “打开完整日历”使用顶层导航打开，避免完整页继续嵌套在 iframe 中。

## 管理端独立 HTML 原型

### 交付边界

- 新建独立静态 HTML，建议路径：`docs/prototypes/calendar-admin-v2.html`。
- 原型可直接双击打开，使用模拟分类、日程和预设数据。
- 不修改现有管理端 HTML、管理脚本、服务端路由或数据库。
- 用户验收通过前，不执行接入工作。

### 页面结构

- 左侧为步骤导航：基本信息、日期与重复、组合任务、颜色与说明、预设。
- 右侧为当前步骤的大编辑区，字段分组和帮助文字清晰。
- 顶部显示当前编辑状态与“新建日程”。
- 底部固定显示主要动作：保存草稿、保存为预设、完成日程。
- 页面下部或独立抽屉展示预设库与已配置日程。

### 原型交互

- 可切换普通日程/组合日程。
- 可切换连续日期/不连续日期以及开启重复。
- 可调整持续天数并看到结束日期预览。
- 可选择分类联动颜色、暖色色板或输入色值。
- 可添加模拟组合子任务。
- 可切换步骤、套用模拟预设和查看模拟日程，不执行网络请求。
- 桌面端重点展示左侧步骤导航；手机端自动改为顶部横向步骤标签。

## 错误处理与兼容

- 全屏、方向锁定和退出锁定均以能力检测和 `catch` 保护，失败只显示提示，不阻断日历。
- 保留周视图、月视图、日期选择、详情弹窗和最近 18 个月范围控制。
- 公开 API 和现有日程数据结构不变。
- 首页仍保持点击活动日历后才加载资源。

## 验证

- 自动测试确认首页“全部”不会加载或显示活动日历，点击活动日历才创建 iframe。
- 自动测试确认预览状态文案、完整日历链接、横竖屏按钮和方向能力检测存在。
- CSS 测试确认横屏、竖屏模式都取消日历横向滚动，七列使用视口内等分布局。
- 自动测试确认活动日历隐藏自动注入的悬浮主题按钮。
- 自动测试确认管理端原型完全独立，不引用管理接口或替换现有管理页。
- JavaScript 语法检查、日历专项测试和相关首页回归必须通过。
