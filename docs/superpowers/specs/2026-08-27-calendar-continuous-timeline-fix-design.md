# 默认连续时间轴修复设计

## 目标

修复活动日历“默认时间轴”只显示前 7 天的问题，使其按照现有范围、导航和拖动逻辑展示连续 56 天；同时让手机端的周/月网格一屏显示完整 7 天，并让连续时间轴每屏显示 7 天后继续横向滚动。

## 根因

`currentRange()` 为时间轴生成 56 天范围，导航每次移动 56 天，拖动逻辑也只在时间轴视图启用；但 `render()` 的时间轴分支错误调用 `renderWeek()`，只渲染范围中的第一周。项目已经存在完整的 `renderTimeline(range)` 实现和配套 CSS。

## 修改范围

- 将 `public/function/calendar-gantt.js` 的时间轴渲染分支恢复为 `renderTimeline(range)`。
- 保留现有 56 天范围、56 天翻页、鼠标拖动和触屏滚动逻辑。
- 保持周视图和月视图行为不变。
- 更新 `public/function/calendar.html` 中 `calendar-gantt.js` 和 `calendar-gantt.css` 的缓存版本号。
- 更新 UI 回归测试，明确验证时间轴分支实际调用 `renderTimeline(range)`，而不只是检查该函数存在。
- 在 `public/function/calendar-gantt.css` 增加 `max-width:760px` 自适应规则：压缩页面留白和分类列，七个日期列平分剩余宽度，缩小日期、分类和卡片文字。
- 手机端滚动容器建立 inline-size 容器；分类列固定为 `64px`，周/月视图用 `64px + repeat(7,minmax(0,1fr))` 精确占满容器。
- 手机端连续时间轴以 `calc((100cqw - var(--category-width)) / 7)` 计算单日列宽，使分类列和 7 天恰好占满滚动容器，并保留横向滚动以浏览其余 49 天。
- 独立页面和 `?embed=1` 首页预览使用同一套手机端规则。

## 不在本次范围内

- 不删除 HTML 中的时间轴 DOM 去重观察器。
- 不调整桌面端时间轴尺寸、颜色、分类或卡片样式；手机端只做必要的尺寸压缩。
- 不修改日历 API、领域模型和数据库。

## 验证

1. 先增加“时间轴分支必须调用 `renderTimeline(range)`”的回归测试，并确认当前代码失败。
2. 恢复连续时间轴调用后确认该测试通过。
3. 运行日历 UI、领域逻辑和路由测试。
4. 增加手机端布局源码测试，验证规则限定在最终的 `max-width:760px` 块内，7 列平均分配，周/月视图不溢出，时间轴单日宽度按容器剩余宽度的七分之一计算且仍可横向滚动。
5. 在独立页面和 `?embed=1` 下分别以 360px、760px 宽度检查“分类列 + 7 天”；以 761px 检查桌面规则继续生效。
6. 确认桌面基础规则和周/月 JavaScript 分支未变化。
