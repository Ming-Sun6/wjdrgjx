# 活动日历管理 V2 正式接入设计

## 目标

把已经验收的 `docs/prototypes/calendar-admin-v2.html` 视觉结构接入现有管理页，同时完整保留当前活动分类、日程、循环、组合任务、预设和筛选功能。正式页面继续使用现有管理认证、接口和数据库，不引入新的数据格式，也不改变公开活动日历的数据来源。

## 约束与边界

- 只改生产管理页中 `#page-calendar`、`admin-calendar-page.css` 和必要的 `admin-calendar-page.js` 交互。
- 保留现有表单控件 ID、请求 URL、HTTP 方法和请求载荷，避免破坏已经上线的数据与 CDN 兼容处理。
- 不把独立原型以 iframe 方式嵌入后台；原型仍作为验收参考文件保留。
- 不修改日历数据库结构、服务端路由、公开日历渲染逻辑或首页。
- 不删除任何现有能力：分类新增/编辑/排序/停启用，日程新增/编辑/复制/删除/停启用，连续日期、不连续日期、起止时间、颜色、循环规则、组合任务、预设保存/套用/删除和列表筛选都必须继续可用。

## 页面结构

生产页采用与验收原型一致的工作台结构：

1. 顶部标题区显示“活动日历管理 V2”、简短说明、当前加载状态、刷新和新建日程入口。
2. 主编辑区左侧为五步导航：基本信息、日期与重复、组合任务、颜色与说明、预设；右侧每次只显示当前步骤。
3. 基本信息中先用卡片选择普通日程或组合日程，再显示名称、分类和启用状态。
4. 日期与重复中整合连续日期、不连续日期、起止时间和循环规则；循环是普通/组合日程都能开启的选项，不再作为独立日程类型。
5. 组合任务步骤在普通日程下显示说明，在组合日程下提供甘特任务块/每日清单及子任务编辑。
6. 颜色与说明使用暖色调色板、原生颜色选择器和十六进制输入，并保留“跟随分类颜色”。
7. 预设步骤包含“保存当前配置为预设”和现有服务器预设列表。
8. 编辑器底部保留取消、保存为预设和保存日程；桌面端固定在编辑器底部，手机端改为普通两列布局，主保存按钮独占一行。
9. 编辑器下方保留活动分类与已配置日程两个资料区，避免把维护功能混入创建步骤；分类和日程仍使用真实服务端数据。

## 响应式行为

- 宽屏使用左侧步骤栏和右侧编辑器；资料区为两列。
- 900px 以下步骤栏移到编辑器上方。
- 560px 以下步骤按钮换成两列并完整显示，不横向滚动；所有表单变为单列，操作按钮保持至少 40px 高。
- 不改变整个后台的公共导航、主题或权限布局。

## 交互与数据流

- `loadAdminCalendar()` 仍负责首次绑定并并行加载分类、日程和预设。
- 步骤按钮只切换本地可见面板，不触发网络请求，也不丢失未保存表单内容。
- 编辑日程、复制日程或套用预设时自动回到“基本信息”步骤，并更新标题和帮助说明。
- 选择普通/组合结构、连续/不连续日期、重复开关时继续调用现有可见性与载荷构建逻辑。
- 保存日程和预设继续使用现有接口。成功后刷新对应列表；失败时在顶部状态区显示服务端错误，不清空表单。
- 新建/取消编辑清空表单并回到第一步。
- 分类维护继续使用现有真实接口，视觉上放在主编辑器下方的独立卡片中。

### 接口契约保持不变

| 功能 | 方法与地址 | 必须保持的关键数据 |
| --- | --- | --- |
| 分类列表/新增 | `GET/POST /api/admin/calendar/categories` | `id`、`code`、`name`、`color`、`sortOrder`、`enabled` |
| 分类编辑 | `POST /api/admin/calendar/categories/:id` | `name`、`color`；服务端继续兼容 `PATCH` |
| 分类排序/状态 | `POST /api/admin/calendar/categories/reorder`、`POST /api/admin/calendar/categories/:id/status` | 完整 `ids` 顺序、`enabled` |
| 日程列表/新增 | `GET/POST /api/admin/calendar/schedules` | 下述完整日程载荷 |
| 日程编辑 | `POST /api/admin/calendar/schedules/:id` | 下述完整日程载荷；服务端继续兼容 `PATCH` |
| 日程复制/状态/删除 | `POST .../:id/copy`、`POST .../:id/status`、`DELETE .../:id` | 复制不覆盖原记录，状态仅改 `enabled` |
| 预设列表/新增/删除 | `GET/POST /api/admin/calendar/presets`、`POST .../:id/delete` | `id`、`name` 与完整 `payload` |

日程读取、填充和保存必须往返保持：`categoryId`、`name`、`scheduleType`、`startDate`、`endDate`、`legacyDates`、`startTime`、`endTime`、`color`、`description`、`enabled`、`recurrenceUnit`、`recurrenceInterval`、`weekdays`、`monthDay`、`recurrenceEndType`、`recurrenceUntil`、`recurrenceCount`、`compositeLayout` 和 `items`。测试必须覆盖“加载已有记录 → 只改名称 → 保存”，验证无关字段不丢失或变形，而不是只匹配接口字符串。

### 日期、循环与颜色保留标准

- 父日程持续天数保留 `1–366` 范围；修改开始日期或持续天数后，立即同步只读结束日期和中文日期预览。
- 保留“今天、明天、下周同一天”快速日期按钮；不连续日期继续支持换行、空格和中英文逗号输入，去重排序，并在没有有效日期时阻止保存。
- 普通和组合日程都可开启重复，且一次出现可持续多天。循环继续支持天/周/月、间隔、星期、每月第几日，以及长期/截止日期/次数三种结束方式。
- 跟随分类色时，手动颜色控件视觉禁用并保存 `color: null`；关闭跟随后，色板、原生颜色选择器和十六进制输入保持双向同步并保存 `#RRGGBB`。
- 在步骤、普通/组合结构、连续/不连续方式之间切换时，不主动清除用户刚填写但暂时隐藏的值；只有明确执行新建或取消编辑才重置表单。

### 组合子任务保留标准

每个组合子任务必须完整保留 `id`、`name`、`description`、`color`、`sortOrder`、`highlighted`、`enabled`、`dateMode`、`startTime` 和 `endTime`。四种日期模式继续可用：

- `all-span`：覆盖整个父日程。
- `relative-range`：保留 `startOffsetDays`、`endOffsetDays`。
- `selected-days`：保留去重排序后的 `selectedOffsets`。
- `recurring`：保留 `durationDays`、`recurrenceUnit`、`recurrenceInterval`、`weekdays`、`monthDay`、`recurrenceEndType`、`recurrenceUntilOffset` 和 `recurrenceCount`。

切换子任务日期模式只改变相关字段的可见性，不删除其暂存值。填充旧组合日程后只修改父级名称并保存，所有嵌套子任务字段必须原样往返。

### 预设语义保持不变

- 保存预设时保存当前完整日程载荷，但不保存日程和子任务的数据库身份字段。
- 套用预设始终进入“新增日程”而不是覆盖当前编辑记录。
- 套用时把最早日期平移到当天，并保持持续天数、不连续日期间距、循环配置、组合布局和全部嵌套子任务不变。
- 套用后允许继续修改并另存为正式日程；保存或删除预设成功后刷新预设列表。
- 保存/套用/删除失败时显示错误且保留当前表单内容；删除继续要求确认。

## 可访问性与错误处理

- 所有步骤和结构选择器使用 `button type="button"`，维护 `aria-selected` 或 `aria-current` 状态。
- 隐藏步骤面板使用 `hidden`，避免其中控件参与键盘导航或原生表单校验。
- 现有表单继续使用 `novalidate` 和脚本校验，避免隐藏控件触发“not focusable”。
- 网络失败保留用户输入，并在 `#calendarAdminStatus` 显示明确错误。
- 删除日程、删除预设等破坏性操作继续二次确认。

## 测试与验收

- 静态结构测试验证五步导航、五个面板、真实控件 ID、真实列表容器和脚本/CSS版本引用。
- 脚本测试验证步骤切换、新建/编辑/套用预设回到第一步、现有接口 URL 和 POST 兼容逻辑仍存在。
- 增加可执行的表单往返测试：分别覆盖普通连续循环、不连续日期、组合日程，以及组合子任务的 `all-span`、`relative-range`、`selected-days`、`recurring` 四种模式；只改无关字段后断言其余载荷深度相等。
- 预设测试覆盖完整载荷保存、身份字段剥离、套用进入新增状态、日期平移、嵌套组合和循环字段保持、删除确认与失败保留输入。
- 日期与颜色测试覆盖快速日期、持续天数和结束日期同步、不连续日期校验、分类色跟随，以及色板/原生取色器/十六进制输入的双向同步。
- 既有日历领域、路由、预设、存储及管理页测试必须全部通过。
- 使用本地静态页面对桌面宽度和 390px 手机宽度截图，确认无横向溢出、操作按钮可见、五步导航完整。
- 生产后台只在管理认证后加载真实数据；不在测试或原型中发生产 API 请求。
